## 什么时候用

用户要求运行测试、确认测试状态，或询问测试为什么失败时。

## 步骤

1. 先运行 `python -m pytest -q`，不要一上来就加 `-v`。
2. 如果项目已有专用测试命令，优先使用项目文档中的命令。
3. 只读取失败用例的 traceback，最多检查前 3 个失败。
4. 把每个失败整理成四行：用例 / 期望 / 实际 / 最可能原因。
5. 汇总通过数、失败数、跳过数；不要声称未运行过的测试通过。
6. 如果失败来自环境或缺少依赖，写清楚具体缺少什么。

## 不要做什么

- 不要顺手修改业务代码；这个技能只负责运行和报告。
- 不要为了让测试变绿而删除测试或放宽断言。
- 不要把完整 traceback 全部贴回上下文。
- 不要在没运行测试时猜测结果。

## 怎么算做完了

- 有一条真实测试命令及其退出码。
- 有通过 / 失败 / 跳过的数量。
- 每个失败都有可复现的用例名和下一步建议。

## 输出模板

```
测试命令：...
结果：X passed, Y failed, Z skipped
失败用例：...
期望：...
实际：...
最可能原因：...
建议下一步：...
```

如果全部通过，仍要写出命令、耗时范围和覆盖范围；不要把“没有失败”写成“所有功能正确”。
