## 什么时候用

用户要求 review 当前改动、审阅补丁，或想知道一次修改是否安全时。

## 步骤

1. 先运行本技能目录下的 `scripts/collect_diff.py`，不要手工拼接 diff。
2. 默认检查未暂存改动；用户要求时加 `--staged`。
3. 按严重程度检查：正确性、数据丢失、安全、兼容性、测试覆盖。
4. 每条发现必须包含文件、问题、影响和最小修复建议。
5. 没有发现问题时明确写“未发现阻塞性问题”，并说明检查范围。
6. 不修改代码，除非用户在同一条请求里明确要求修复。

## 脚本调用

技能加载结果会给出本技能目录。使用类似命令：

```bash
python "<skill-dir>/scripts/collect_diff.py" --max-lines 400
```

需要检查暂存区时：

```bash
python "<skill-dir>/scripts/collect_diff.py" --staged --max-lines 400
```

## 不要做什么

- 不要只复述 diff。
- 不要因为格式问题淹没真正的正确性风险。
- 不要把“我没看到问题”写成“绝对没有问题”。
- 不要在 review 阶段自动提交或自动回滚。

## 怎么算做完了

- 覆盖了 diff 中所有改动文件。
- 每条风险都有定位和影响。
- 明确区分阻塞问题、建议和未覆盖项。

## 严重度

- 阻塞：会导致错误结果、数据丢失、安全问题或现有测试失败。
- 重要：在常见路径上可能出错，或缺少关键边界处理。
- 建议：可维护性、命名、重复代码和轻微性能问题。

## 检查顺序

先看改动是否改变公开行为，再看错误路径和边界条件，最后看测试是否覆盖新分支。不要先花时间讨论纯格式问题。
